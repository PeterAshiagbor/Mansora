# C50 — reviewed WhatsApp drafts and customer statements

Authorised users can prepare a receipt draft from Sales history, an individual unpaid-credit reminder from Credit & repayments, or a current customer statement from Customers. Existing engine reads supply every amount; no broader command or permission is introduced. Cashiers still cannot read another cashier's sale, and credit/customer tools retain their existing permissions.

Every action opens a review dialog first. The user must provide/check a full international number and affirm the intended recipient and appropriateness of sharing. Local numbers are not assigned a guessed country code. Changing the number clears confirmation. The final explicit action opens an HTTPS wa.me draft using the existing safe external-link path. Opening passes the preview/number to WhatsApp; sending is a separate choice in WhatsApp. Mansora does not call a messaging provider, mark anything delivered, create a payment link or record a financial event.

Receipt text distinguishes the original sale total, recorded payment methods (credit is not money received), refunds and remaining credit. Debt reminders use the current outstanding balance rather than original credit. Statements list current per-receipt balances and their total, with an as-of date; they do not reconstruct a historical balance. A separate printable statement uses the existing escaped table renderer and print/PDF mechanism. WhatsApp deep links cannot automatically attach a PDF: save/print and attach it manually when needed.

To avoid silently dropping financial detail, messages over 6,000 characters cannot be opened through this action; the dialog directs the user to the printable/file path. No supervisor credentials, costs, hidden identifiers or customer notes are added to the message. The review does not establish that the number belongs to a customer; the operator must verify it and observe the business's privacy obligations.

Validation covers explicit number handling, URL encoding, length bounds, current balances after a real partial repayment, receipt credit semantics, confirmation gating and accessible review dialogs. Browser tests intercept window.open to inspect the draft; no actual WhatsApp request or message is sent. Real sale/credit balances are asserted unchanged after preparing drafts and a printable statement. Exact full-suite and release evidence belongs in the task-board handoff.
